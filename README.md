# PRINCE ARCHIVE AI

تطبيق ويب (React) مع نقطة API خادمية واحدة (Vercel Serverless Function) وربط حقيقي ببحث Gallica BnF.

## البنية
- `index.html` — التطبيق الرئيسي (SPA)
- `admin.html` — لوحة إدارة حقيقية (راجع أدناه)
- `api/gallica.js` — دالة خادمية (Node.js على Vercel) تتصل فعليًا بـ API مكتبة BnF الفرنسية (Gallica SRU) وتُرجع نتائج حقيقية، لا بيانات وهمية
- `vercel.json`, `.gitignore`

## البحث الحقيقي (Gallica)
عند إجراء بحث في تبويب "الأرشيف العام"، يتصل الموقع بـ `/api/gallica?q=...` الذي يستدعي خادميًا:
`https://gallica.bnf.fr/SRU?operation=searchRetrieve&version=1.2&query=...`
النتائج الحقيقية تظهر أولاً معلّمة بـ "LIVE" و"Gallica BnF (LIVE)"، تليها النتائج التوضيحية الثابتة الأخرى (المحاربون، ANOM، إلخ — هذه ما زالت بيانات نموذجية لعدم توفر API عامة لتلك المؤسسات).

## لوحة الإدارة (`/admin.html`)
صفحة مستقلة تقرأ البيانات الحقيقية المخزّنة في متصفحك (`localStorage`): المستخدمون، سجلات البحث، المفضلة، شجرة العائلة، التنبيهات، منشورات المجتمع، التبرعات. كما تعرض فحص صحة حي (live health check) لاتصال Gallica.

**أول استخدام:** سجّل حسابًا من الموقع الرئيسي ووثّقه (الزر في شاشة "التحقق" بعد التسجيل)، ثم افتح `/admin.html` وسجّل الدخول بنفس البيانات. بما أنه لا يوجد أي مشرف بعد، ستظهر لك شاشة "أصبح مشرفًا الآن" — اضغطها مرة واحدة فقط. بعدها لن تظهر هذه الشاشة لأي حساب آخر.

⚠️ ملاحظة أمنية: نظام الحسابات بالكامل يعمل من جهة المتصفح فقط (لا خادم قاعدة بيانات حقيقي)، لذا أي شخص يملك أدوات المطوّر في متصفحه يمكنه نظريًا تعديل `localStorage` الخاص به. هذا مقبول لنموذج تجريبي/شخصي، وليس كافيًا لموقع إنتاجي يخزّن بيانات مستخدمين حقيقيين حسّاسة.

## النشر
1. ارفع كل هذه الملفات (بما فيها مجلد `api/`) إلى مستودع GitHub.
2. في Vercel: Import المشروع — سيتم اكتشاف `api/gallica.js` تلقائيًا كدالة خادمية (لا حاجة لأي إعداد build، Vercel يتعرف على مجلد `api/` تلقائيًا).
3. بعد النشر، جرّب: `https://<رابطك>/api/gallica?q=Abdelkader` يجب أن يُرجع JSON حقيقي من Gallica.
